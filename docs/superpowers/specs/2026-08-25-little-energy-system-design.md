# 小能仔统一视觉、情绪同步、换装与聊天 Emoji 设计

## 目标

在 iOS 与 Windows 两端建立统一的小能仔视觉与状态体系：将现有情绪、人格和角色表情替换为小能仔；把今日情绪打卡扩展到 27 种并驱动当天全局角色状态；为当前用户增加可持久化的分部件换装；在聊天中提供同一套 27 个小能仔自定义 Emoji。保留现有内容、布局风格和业务数据，避免并行状态源。

## 范围

### 包含

- iOS（SwiftUI）与 Windows（Electron）客户端。
- Node.js/Express 服务端的数据模型、兼容迁移与接口。
- 27 种小能仔情绪素材、状态定义和聊天 Emoji。
- 用户小能仔的上衣、下装、鞋子、配饰独立选择及跨设备同步。
- 当前用户、其他正常用户、被吐槽同事三类角色的显示规则。
- 现有情绪趋势、AI 总结、人格、用户卡片和聊天消息的兼容。

### 不包含

- 角色骨骼动画或实时 3D 渲染。
- 商城、解锁、付费服装和库存系统。
- 用黑化形象作为用户可选服装或用户当天情绪。
- 与本功能无关的页面重构。

## 核心原则

1. 后端保存稳定 ID，图片仅作为客户端资源，不把图片二进制写入业务记录。
2. 今日情绪以现有每日打卡记录为唯一数据源；客户端全局状态仅缓存服务端结果。
3. 用户穿搭以用户资料中的一份结构化配置为唯一持久化数据源。
4. iOS 与 Windows 使用同一份规范化资源清单和完全一致的 ID。
5. 黑化小能仔与正常用户小能仔严格隔离，只表示被吐槽的同事形象。
6. 所有未知或缺失资源均回退到默认小能仔，不能显示破图或空白。

## 资源体系

### 情绪目录

建立 27 个稳定情绪 ID，覆盖参考图中的：开心、快乐、平静、兴奋、自豪、爱心、感激、期待、惊讶、担忧、焦虑、疲惫、压力大、难过、失望、孤独、烦躁、愤怒、嫉妒、尴尬、愧疚、困惑、震惊、坚定、斗志、从容、困倦。

每个定义至少包含：

- `id`：跨端和后端使用的稳定英文标识。
- `label`：中文显示名。
- `legacyEmoji`：可选的历史系统 Emoji 映射。
- `score`：趋势图和 AI 汇总使用的情绪强度。
- `assetName`：客户端本地资源名。
- `fallbackText`：旧客户端或资源缺失时的兼容文字。

新打卡记录只保存稳定 ID。服务端读取历史 `😄/🙂/😐/😮‍💨/😡/💀` 时映射为最接近的新情绪 ID，写接口在过渡期同时接受旧 Emoji 与新 ID。

### 正常用户角色

正常用户小能仔由基础身体、当天情绪表情和穿搭图层合成。图层统一画布尺寸、锚点、缩放和层级，保证 iOS 与 Windows 视觉一致。没有当天打卡时使用默认开心状态；缺失穿搭时使用默认套装。

### 黑化同事角色

黑化小能仔为独立资源族，只用于被吐槽同事、同事档案、同事人格及相关摘要。它不读取用户穿搭，也不能出现在换装选择器中。

### 换装目录

首版支持四类独立选择：

- 上衣：参考图中的短袖、衬衫、卫衣、针织衫、西装外套、棒球服等。
- 下装：休闲裤、牛仔裤、工装裤、短裤、半身裙等。
- 鞋子：运动鞋、帆布鞋、皮鞋、马丁靴、休闲鞋等。
- 配饰：眼镜、帽子、耳机、手表、项链、戒指、手链、背包、托特包、斜挎包、腰带及参考图中的发饰；配饰允许选择“无”。

可提供整套穿搭作为快捷预设，但保存结果始终展开为四类单品 ID，避免第二套数据结构。

## 状态与数据流

### 今日情绪

1. App 启动、登录完成或首页刷新时调用现有今日情绪接口。
2. 服务端返回当天打卡记录及规范化情绪 ID。
3. 客户端写入现有全局 Store（iOS 为 `MockDataStore.moodToday`；Windows 扩展现有 `App.state`），不创建页面私有的长期副本。
4. 首页顶部角色、情绪卡、AI 洞察、人格摘要及其他当天情绪展示都从该全局状态派生。
5. 用户在快速打卡或完整打卡中选择任一情绪后，服务端 upsert 成功即更新全局状态；所有已订阅页面立即重绘。
6. 同一天再次编辑时覆盖原记录并同步更新所有页面。

### 用户穿搭

用户资料增加结构化穿搭配置：

```json
{
  "topId": "top_shirt",
  "bottomId": "bottom_slacks",
  "shoesId": "shoes_sneakers",
  "accessoryIds": ["accessory_glasses"]
}
```

编辑资料页面维护临时预览值。只有保存接口成功后才更新全局 `currentUser`；失败时保留编辑预览、显示错误，并保持其他页面仍使用上一次成功保存的配置。服务端返回用户资料的所有接口都包含规范化穿搭配置，使个人页、用户卡片、聊天头像及其他展示该用户小能仔的位置自动一致。

### 聊天 Emoji

聊天输入区新增小能仔 Emoji 面板，列出同一套 27 个情绪。发送记录使用独立消息类型和稳定 ID：

```json
{
  "mediaType": "little_energy_emoji",
  "mediaUrl": "xnz_happy",
  "text": "[小能仔·开心]"
}
```

优先复用现有 `media_type`、`media_url` 和 `text` 字段，避免新增平行消息表或大图片传输。新客户端按 ID 渲染本地资源；旧客户端显示 `text` 中的兼容内容。普通文字、图片、语音、订单及系统消息不变。

## 页面修改

### iOS

- 首页顶部增加主小能仔，情绪和穿搭由全局状态派生。
- 今日情绪快速选择与完整打卡扩展为 27 项小能仔网格。
- AI 洞察、人格卡、情绪趋势和所有系统 Emoji 情绪展示改用统一组件。
- 我的页和用户资料卡使用统一角色组件。
- 编辑资料增加分部件换装、实时预览、预设套装和保存反馈。
- 消息输入区增加小能仔 Emoji 面板，消息气泡支持自定义 Emoji 类型。
- 被吐槽同事相关页面统一使用黑化资源。

### Windows

- 首页、情绪打卡弹窗、AI 洞察、人格卡、用户卡片与 iOS 使用同一 ID 映射。
- 我的/编辑资料增加与 iOS 等价的分部件换装和预览。
- 聊天输入区增加 27 项小能仔 Emoji 面板，消息列表支持相同消息类型。
- 被吐槽同事相关卡片统一使用黑化资源。
- 保留现有桌面布局与交互密度，只替换角色资产及必要控件。

## 服务端修改

- 为 SQLite 与 MySQL 的 `users` 表增加可空的穿搭配置字段，使用幂等迁移兼容已有数据库。
- 用户序列化与资料更新接口读写并校验穿搭配置；未知单品 ID 回退或拒绝，不能保存任意路径。
- 情绪接口接受 27 个稳定 ID，并兼容历史 6 种 Emoji。
- 趋势和 AI 总结使用情绪定义中的分值与正负向分组，不再硬编码旧 6 Emoji。
- 聊天接口允许 `little_energy_emoji` 媒体类型，并校验 ID 属于 27 项白名单。
- 不新增重复的今日情绪字段到用户表。

## 异常与兼容策略

- 未知情绪 ID：显示默认开心小能仔，并保留可读的原始标签用于诊断。
- 未知服装 ID：该图层回退到默认单品；未知配饰忽略。
- 本地资源缺失：统一回退默认角色资源，不显示空白。
- 穿搭保存失败：不更新全局已保存状态，允许用户重试。
- 打卡失败：保持原当天状态，显示现有错误反馈。
- Emoji 发送失败：沿用现有消息失败/重试行为。
- 旧客户端收到自定义 Emoji：显示兼容文本 `[小能仔·情绪名]`。
- 旧情绪记录：服务端响应时规范化，数据库可保留原值以降低迁移风险。

## 测试与验收

### 自动测试

- 服务端：27 种情绪校验、旧 Emoji 兼容、同日覆盖、趋势与总结分值、穿搭保存与读取、非法单品、聊天 Emoji 校验及旧客户端兼容文本。
- Windows：共享清单完整性、打卡后全局同步、换装组合与保存、聊天 Emoji 发送/接收、未知 ID 回退；运行现有核心和 v2 回归测试。
- iOS：为纯映射和组合逻辑增加可执行测试或轻量断言；执行 Swift 项目静态检查，并通过 GitHub Actions 的 Xcode 构建验证。
- 资源检查：自动验证 27 个情绪 ID 在两端都有对应资源，服装图层尺寸与命名符合清单。

### 手工验收

1. iOS 与 Windows 登录同一账号，任一端完成打卡，刷新另一端后状态一致。
2. 同一端打卡成功后无需重启或切页，首页顶部和所有可见情绪展示立即变化。
3. 分别修改上衣、下装、鞋子和配饰并保存，个人页及所有当前用户角色展示同步变化；重新登录仍保留。
4. 聊天发送 27 种小能仔 Emoji，双方客户端均显示正确图片，旧客户端至少显示兼容文字。
5. 被吐槽同事始终显示黑化小能仔，且换装列表中不存在黑化服装。
6. 历史 6 种 Emoji 打卡记录仍可查看，趋势和 AI 总结无异常。
7. 现有页面内容、导航和主要布局保持不变。

## 实施约束

- 先写失败测试再改生产代码，按情绪模型、穿搭资料、聊天 Emoji、跨端 UI 的顺序逐步落地。
- 尽量复用 `MockDataStore`、`App.state`、现有用户资料接口和聊天媒体字段。
- 角色素材基于用户提供的三张原始参考图及穿搭图鉴重新制作透明资源，不直接把带白底的整图裁块作为最终资产。
- 不在本功能中引入新的前端框架或第三方状态管理库。
- 完成后运行服务端测试、Windows 全部现有测试与语法检查，并以 GitHub Actions 验证 iOS 构建。
