# 全屏社交体验与小能仔呈现设计

## 目标

将 iOS 与 Windows 的吐槽、搜索、聊天、个人资料与小能仔体验统一为完整页面流，消除服装重叠、情绪代码外露和半页弹层造成的中断感；收藏状态通过服务端在两端同步。

## 已确认的范围

- iOS 与 Windows 同时更新，但 Windows 保持桌面侧栏与内容区，不复制 iOS 底栏。
- 帖子卡中的“共鸣”入口改为“评论”；原有共鸣数据与接口保留兼容，但不再作为主操作显示。
- 收藏是持久化、跨端同步的帖子状态，不是单纯图标。
- 帖子、热搜词、搜索结果、聊天、发帖、换装、编辑资料、个人档案、我的吐槽与收藏均以完整页面呈现。
- 参考图是移动端视觉基准：浅紫背景、白色圆角信息卡、紫色主操作、真实小能仔资源；系统状态栏不属于应用 UI。

## 方案选择

采用完整同步方案，而非“仅重做 UI + 本地收藏”或“先做广场后做其余页面”。这样帖子操作和收藏不会在 iOS、Windows 之间出现不同步，且所有入口可在一个版本中摆脱半页交互。

## 信息架构与导航

### iOS

- `ComplaintTabView` 使用 `NavigationStack` 路由进入广场筛选、帖子详情、热搜结果、搜索结果与发帖页；不再用 `sheet` 承载这些主页面。
- `HomeOverviewView` 的搜索、发帖、AI、情绪完整打卡改为导航目的地或 `fullScreenCover`；只有不可独立浏览的确认动作可保留紧凑弹层。
- `MineView` 将查看主页作为个人档案唯一入口；编辑资料、我的吐槽、我的收藏、浏览记录、同事列表与 AI 页面全部从档案页继续导航。
- `MessageView` 的会话进入 `ChatDetailView` 完整页；会话信息、表情面板和附加动作仅作为页内组件，不使用半页抽屉。

### Windows

- 在 `win-app/src/views.js` 建立内容区页面历史/返回入口：帖子详情、搜索、发布、资料编辑、我的帖子与收藏替换 `openModal`。
- 桌面端保留现有侧栏；只有删除、退出、轻量确认等短操作使用 modal。
- 热搜、卡片点击、搜索分类和个人工具卡均进入完整内容区页面，并提供明确返回按钮。

## 小能仔

- 正常用户角色统一由“情绪头部裁切层 + 一张完整造型层”组成。情绪资源只显示头部/表情区域，完整造型资源负责身体，禁止再渲染上衣、下装、鞋子或配饰商品图。
- iOS `LittleEnergyAvatarView` 与 Windows `littleEnergyAvatarHtml` 共享相同的 look resolver 和裁切规则；首页右上角、情绪打卡、聊天小表情、帖子作者、个人页与换装预览均走这一组件。
- 黑化同事是独立角色，不经过服装 resolver。
- 换装页依图 1：大尺寸透明预览、拖动查看前左后右四角度、可横向浏览的完整造型卡、明确选中态与底部保存按钮。只保存既有 `littleEnergyOutfit` 字段，避免新增第二数据源。

## 广场、帖子与收藏

- 帖子卡保留点赞，主交互改为“评论”和收藏；评论点击进入详情页并聚焦评论列表，收藏支持切换状态。
- 服务端新增 `complaint_favorites` 表（`complaint_id`、`user_id`、`created_at`，唯一约束为帖子与用户）；新增收藏切换与我的收藏接口。
- Feed、我的吐槽、详情与搜索命中补充 `favorited` 与 `favoriteCount`；客户端模型、Store 和 Windows state 使用服务端返回的同一状态。
- 帖子详情为完整阅读页：作者、真实情绪徽标、正文、行为标签、点赞/评论/收藏、评论列表与发表评论。
- 热搜榜每一个词可点击，进入带标题与当前关键词的完整帖子列表；不再只是不可操作的标签。
- 帖子中的情绪通过 `LittleEnergyCatalog.mood(for:)` / Windows `moodById` 映射为中文名称与小能仔资源，任何 `xnz_*` 协议 ID 都不得直出到 UI。

## 发布、聊天与搜索视觉

### 发布

- 依图 2 使用全屏“发吐槽”编辑页：顶栏取消/发布、正文输入区与字数、关联同事、类型、行为标签、今日情绪、匿名开关和底部紫色发布按钮。
- 图片按钮仅在现有客户端能力内提供选择/预览；帖子媒体持久化不在本次范围，因为当前投诉 API 与数据库没有媒体存储字段或对象存储配置。

### 聊天

- 依图 3 调整完整会话页：紧凑导航栏、在线状态、日期胶囊、左右气泡、底部输入条、表情与加号入口，以及隐私提示。
- 小能仔聊天表情继续使用发送方保存的完整造型与情绪，不显示服装层叠或原始 mood ID。

### 搜索

- 依图 4 使用完整搜索页：顶部关闭/标题/搜索框，热门搜索词、四个快捷类别、最近搜索和小能仔空状态。
- 搜索结果按帖子、同事、公司分组；每一个结果进入对应完整详情页或筛选页。

## 数据与兼容性

- 保留现有 `complaint_resonances` 路由与字段，防止旧客户端失败；新 UI 不再提供其主入口。
- 收藏接口使用当前认证与 SQLite/MySQL 双 schema 迁移模式；删除帖子时级联或显式清理收藏。
- 情绪仍只使用既有稳定 ID 与 catalog 映射，服务端响应保持向后兼容。
- 所有新页面复用 `MockDataStore`、`APIClient`、Windows `api.js` 已有状态所有权，禁止重复缓存用户、情绪、收藏或帖子数据。

## 验收标准

1. 首页、情绪打卡和聊天中看不到服装商品图或重叠身体；黑化同事不穿衣服。
2. 点击帖子、热搜、搜索结果、个人工具和聊天会话进入完整页面，而非半页弹层。
3. 广场显示评论与收藏；收藏后 iOS、Windows 刷新均保持一致。
4. 所有帖子情绪以中文和小能仔视觉表达，不出现 `xnz_*`。
5. 发帖、换装、聊天、搜索与个人档案在相同状态下与四张参考图的层级、留白和交互语义一致。
6. 服务端路由测试、Windows 逻辑/UI 回归测试、iOS 模型/导航测试通过；Windows 重新打包，GitHub macOS CI 成功。
